# Alpha 0.24 — consolidated evidence lifecycle

The initial attestation release remains in Git history (31ceda02c5a976f5d780e73ba6f31408655cebfb). This revision retains both Alpha 0.23 continuation and acquisition behavior: planner.py and test_resume.py had identical Git blobs in both snapshots and are inherited here. The acquisition and strategy integration is retained and regression tested.

- Persist source identity metadata, key fingerprints, configured origin and qualified/limited reliability. Secrets are not stored; explicit reload is required after restart. Rotation or revocation removes invalid support. Supply random high-entropy keys via a trusted local mechanism; the metadata database is not an independent trust anchor.
- Revalidate signed text, parsed fields and candidate identity at each native inference; rebuild the materialized attested facts and withdraw those no longer eligible. Direct Knowledge instances without a verification hook exclude this cache. The reserved attested source prefix cannot be supplied through Knowledge.fact. Manual facts and rules remain unauthenticated, and can independently support conclusions. This is not the V5 cryptographic compare gate.
- Require two distinct configured qualified origins and key fingerprints, with no authenticated opposing evidence. Limited sources cannot contribute positive support but can block promotion. This is conservative policy, not empirically calibrated source reliability or proof of real independence. HMAC authenticates configured key holders, not external facts. No network evidence collection or external identity proof implemented.
- Expose a bounded relationship graph with source, evidence ID, literal, configured origin/reliability and promotion status. Explicit promotion remains mandatory; previously approved facts can be restored if eligibility returns. No open-ended semantic inference or automated truth judgment.
- Queue all persistent objectives, including resolved ones, when the materialized fact set changes. Automatically resume up to eight per explicit trust/evidence mutation or promotion; the durable remainder is processed by continue_research. Inference-triggered refresh queues changes but does not recursively run investigations. Historical reports remain unchanged and a crash between resume and queue removal can replay a report. No background worker, multiwriter guarantee or crash-atomic end-to-end workflow. Revalidation capped at 10,000 attestations and 100 approved literals; on overflow attested premises are withdrawn. Operation bounds are not a strict wall-clock bound.

No paid API, public deployment or actual live language-model inference. Independent held-out comparison and security certification remain outstanding; V5 remains owner-authorized only.
